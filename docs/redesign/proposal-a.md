# UI 재설계 제안 — 지도 한 장, 시트 한 장

**결론.** 앱 전체를 **지도 한 장과 그 위의 바텀시트 한 장**으로 다시 짠다. 홈 대시보드, 목록/지도 토글, 상세 페이지 안의 지도, 대표 코스 카탈로그는 모두 없앤다. 그 자리는 같은 지도 위에서 내용만 바뀌는 시트 세 종류(목록·산·경로)가 맡는다. 길을 지도에 띄우는 방법은 하나뿐이다. **코스 행을 누르면 그 선이 그려진다.** 주변 걷기길은 같은 방식으로 다루는 두 번째 종류의 길이다. 하단 탭바는 없앤다. 중복·저우선 기능은 설정의 토글 12개로 옮기고, 그중 9개는 기본 꺼짐이다.

---

## 1. 핵심 원칙

1. **지도는 바닥이다.** 어느 화면이든 지도가 깔려 있고, 목록·산·경로는 그 위에 시트로 올라온다(기록·설정 화면만 예외).
2. **길 하나에 버튼 하나.** 등산로·대표 코스·계산 경로·걷기길을 모두 "행을 누르면 지도에 그려진다"는 한 가지 동작으로 다룬다.
3. **입구는 한 곳씩만 둔다.** 같은 기능으로 가는 진입점이 두 곳 이상이면 하나를 지운다.
4. **기본 화면에는 처음 오는 사람에게 필요한 것만 둔다.** 나머지는 설정에서 켠다. 토글은 입구만 숨기고, 링크로 들어온 내용은 막지 않는다.
5. **정직성 표시는 작게 두되 늘 데이터 바로 옆에 붙인다.** 예: 계산 경로는 점선, 교차검증 수준은 같은 줄의 글자.

## 2. 정보구조·내비게이션

### 2.1 구조

```
[지도 셸 — 앱 수명 동안 상주하는 MapView 1개]
 ├─ 상단 고정: 검색창 · [기록] · 칩 줄
 ├─ 오른쪽 컨트롤: [레이어] [내 위치]
 └─ 바텀시트 (내용만 교체)
     ├─ 목록 시트   #/  #/map?…           명산 | 걷기길 (설정 시 + 코스)
     ├─ 산 시트     #/m/<id>              탭: 코스 · 주변 길 · 정보
     ├─ 경로 시트   #/m/<id>?route=<key>  선·고도·길찾기·GPX
     └─ 걷기길 시트 #/walk/<id>
[전체 페이지 — 지도 없음]
 ├─ 내 기록 #/track (#/stats 별칭)
 └─ 설정    #/settings
```

**탭바를 없애는 이유**: 홈·지도·코스 탭은 같은 일(산 고르기)을 하고, 남는 목적지는 기록 하나다. NN/g는 탭바를 자주 오가는 4~5개 목적지용으로 본다. 목적지가 둘이면 56px를 상시로 내줄 이유가 없다. 헤더 76px까지 없애 지도 132px를 되찾는다.

**구현**: 라우터는 해시를 그대로 읽되, 지도 계열 라우트 사이에서는 지도를 파괴하지 않고 시트만 바꾼다. 시트 모듈은 라우트 이탈 때 자동 삭제되는 `ctx.layers`에만 그린다.

### 2.2 현재 대비 변경표

| 현재 | 제안 | 비고 |
|---|---|---|
| 하단 탭 4개 + 상단 헤더 | 없음. 검색창 옆 [기록] | 지도 +132px |
| `#/` 홈 대시보드(4,423px) | `#/` = 지도 첫 화면 | 대시보드 내용은 검색 제안·필터·설정으로 흩어 배치 |
| `#/map` 목록 기본, 지도는 토글 뒤 | 지도 기본, 목록은 시트 | 세그먼트 제거 |
| `#/m/<id>` 상세 페이지(4,418px, 지도 내장) | 산 시트(공용 지도) | 탭 3개로 길이를 줄임 |
| `#/courses` 카탈로그(68,724px) | 목록 시트의 '코스' 종류(설정 OFF) | 내용은 산 시트 '코스' 탭에 있음 |
| — | `#/walk/<id>`, `#/map?kind=walk` | 신규 |
| — | `#/settings` | 신규 |

### 2.3 기존 딥링크

| 들어오는 링크 | 처리 |
|---|---|
| `#/map?region&list&all=4&q&hiked=1&sort=near&easy&hours&distance` | 같은 키로 읽고 쓴다. `sort=near`는 권한이 이미 있을 때만 위치를 잰다(기존 규칙) |
| `#/map?…&focus=<id>` | 그 산을 고른 산 시트 peek로 연다. URL은 유지 |
| `#/m/<id>` | 지도를 산에 맞추고 산 시트를 half로 연다 |
| `#/m/<id>?course=<courseId>` | `route=c:<courseId>`의 별칭. 그 선을 그리고 경로 시트를 연다 |
| `#/courses?q=&region=` | `replaceState`로 `#/map?kind=course&q=&region=`. 설정이 꺼져 있어도 이 링크로는 코스 목록을 연다 |
| `#/track`, `#/stats` | 내 기록 |

경로 키(`route=`)의 앞자리: `c:` 대표 코스 id, `t:` 등산로 순번, `g:` 수록·계산 GPX 파일, `w:` OSM 걷기길 relation.

## 4. 지도 상호작용 상세

### 4.1 시트 단계 (844 기준, CSS 변수로 계산)

| 단계 | 시트 높이 | 내용 | 지도 상호작용 |
|---|---|---|---|
| peek | 목록 76 · 산 152 · 경로/걷기길 136 (+safe-area-bottom) | 제목 한 줄(산 시트는 대표 코스 1행 포함) | 가능 |
| half | (뷰포트 − 108) × 0.5 = **368** | 목록 4~5행 / 탭 + 3행 / 고도 단면 | 가능(비모달) |
| full | 뷰포트 − 108 = **736** | 전체 목록·정보 | 상단 108px(검색·칩)만 |

- 시트는 **검색창·칩 줄(0~108px)을 가리지 않는다.** full에서도 검색할 수 있고, "펼친 시트가 페이지처럼 보여 나가는 법을 모름"(NN/g) 문제를 상단 바와 [×]가 막는다.
- 지도 컨테이너는 **peek 윗변**까지만 차지한다(저작권 표시가 늘 보이게). peek 높이가 바뀌면 중심을 유지한 채 relayout한다. half 이상에선 시트 끝에 "지도 © …" 한 줄을 둔다.
- 경로 맞춤은 시트 높이만큼 하단 여백을 둔다. Leaflet `fitBounds(b,{paddingTopLeft:[16,116], paddingBottomRight:[16,H+16]})`, 카카오 `setBounds(b,116,16,H+16,16)`(문서에서 패딩 인자 확인).

### 4.2 제스처·키보드

- **드래그**는 그래버와 시트 헤더(최소 56px)에서 받는다. 놓으면 가까운 단계로 붙고, 속도가 0.5px/ms를 넘으면 진행 방향의 다음 단계로 간다.
- half에서 내용을 위로 스크롤하면 먼저 full로 펼친다(HIG). full에서 `scrollTop=0`일 때 아래로 끌면 half. `overscroll-behavior: contain`.
- **그래버는 `<button>`이다.** 탭·Enter·Space로 peek→half→full→half 순환(HIG), 화살표로 단계 이동, `aria-label="시트 크기: 중간"`.
- **[×] = 뒤로가기 = Esc.** 경로→산→목록 순으로 올라간다. 시트 상태마다 URL이 있어 브라우저 뒤로가기가 동작한다(NN/g). 딥링크로 들어와 이전 기록이 없으면 `#/map`을 replace로 연다.
- 시트는 **한 번에 하나**(HIG·NN/g). 필터·레이어는 모달로 띄우되 그 위에 또 쌓지 않는다.
- 빈 지도를 탭하거나 지도를 끌어도 선택·단계는 바뀌지 않는다(실수 방지).
- 내용이 바뀌면 포커스를 시트 제목으로 옮기고 결과 수는 `aria-live="polite"`. 동작 줄이기 설정에선 애니메이션 없이 전환한다.

### 4.3 컨트롤 배치

| 위치 | 컨트롤 | 근거 |
|---|---|---|
| 상단 8–56 | 검색창(왼쪽, 폭 = 화면 − 16×2 − 기록 버튼 56) · [기록] 48×48 | 지도 앱의 검색 위치 관습. 기록은 빈도가 낮아 오른쪽 위 |
| 상단 64–100 | 칩 3개: `[명산│걷기길]` `[필터 n]` `[가까운 순]` | 가로 스크롤 없이 358px 안에 들어간다(140+84+96+간격) |
| 오른쪽 가장자리, 시트 윗변 12px 위 | [레이어] [내 위치] 44×44, 간격 8 | 시트와 함께 오르내린다. full에서는 숨긴다 |
| 확대·축소 | 터치 기기에선 숨김(핀치), 마우스 기기에선 오른쪽 아래 | 설정에서 바꿀 수 있다 |
| 제거 | 전체화면 버튼·전체화면 검색, 상시 범례, 지도 종류 세그먼트, 상세 지도 아래 버튼 4개 | |

**엄지 영역은 근거로 삼지 않았다.** Hoober 글의 편집자 주는 "도달 영역 그림은 과했고 주로 가운데를 누른다"고 정정했고, NN/g도 바텀시트의 도달성 주장을 "대체로 틀렸다"고 본다. 배치 근거는 **지도를 덜 가리는가**와 **관습**이다.

**정렬**은 `[가까운 순]` 칩 하나다(끄면 기본순). 켜면 시트 헤더에 "3분 전 위치 기준"을 표시하고 내 위치와 가장 가까운 5곳에 지도를 맞춘다.

**필터**는 모달 시트다. 즉시 반영되고 결과 수가 하단 버튼("31곳 보기")에 늘 보인다(NN/g 패싯 검색). 적용 조건은 목록 시트 헤더의 토큰으로 하나씩 해제한다. '미등정'(`hiked=0`)을 추가한다.

**검색**: 빈 창에 포커스하면 최근 본 산과 테마 키워드(단풍·억새·계곡·일출·대중교통)를 제안한다. 입력하면 **명산/코스/걷기길** 묶음별 최대 3개를 보여 주고, 코스를 고르면 바로 경로 시트로 간다. IME 조합 중 Enter는 무시한다(기존 처리 재사용).

### 4.4 마커

- 정상 기호 △(미등정)·▲(등정). 시각 14px, 터치 44px. 권역 색은 기본 끔이다. 위치가 이미 권역을 말해 준다.
- 이름 라벨은 z≥9부터, 12px에 halo.
- 겹친 마커를 누르면 "이 근처 3곳"을 peek로 띄운다(떠 있는 패널을 시트로 통합). 마커 팝업은 없애고, 데스크톱 hover 미리보기는 유지한다.

### 4.5 길을 지도에 띄우는 단일 진입점

**규칙: 코스 행(또는 지도 위의 선)을 누르면 → 그 선이 그려지고 → 경로 시트 peek가 열린다.** 그 밖의 방법은 없다.

선은 **가장 좋은 소스 하나**를 자동으로 고른다. ① 수록 GPX(실선) → ② 빌드 때 구운 계산 경로 721개(**점선** + "계산 경로") → ③ 실시간 OSM 라우팅(점선 + "계산 경로") → ④ 들머리→정상 직선(회색 가는 점선 + "직선 참고 · 등산로 아님"). 변형이 있으면 경로 시트에 `[기본 | 대안 1]`을 둔다.

대표 코스 304개 중 277개는 `trail_index`로 등산로와 이어져 있으므로 **한 행으로 합친다.** 등산로의 수치·교차검증과 대표 코스의 경유지·선정 근거·출처·확인일이 한 행에 들어간다. 연결이 없는 27개는 따로 행을 두고, 선이 없으면 "지도 선 없음 · 경유지"로 표시한다.

지도 위의 선을 눌러도 같은 동작이다(허용 오차 16px, 기존 `nearbyRoutes`). 겹치면 "이 위치의 경로 2개"를 띄운다. 하나를 고르면 다른 선은 사라진다. 여러 개를 겹쳐 보려면 설정 '경로 여러 개 겹쳐 보기'를 켜며, 그러면 행마다 체크박스가 붙는다.

## 5. 주변 하이킹·트레킹 경로

### 5.1 어디서 보이나 (세 곳, 각자 역할이 다르다)

| 위치 | 언제 | 보여 주는 것 |
|---|---|---|
| 산 시트 '주변 길' 탭 | 산을 골랐을 때 | 정상에서 **10km 안**을 지나는 걷기길. 정상까지 거리순. 탭을 열면 그 선들을 지도에 얇게 그린다 |
| 걷기길 모드(칩 `[걷기길]`) | 산과 무관하게 길을 찾을 때 | 지도 범위 안의 걷기길 목록과 선. 명산 △는 30%로 흐림 |
| 걷기길 시트 `#/walk/<id>` | 길 하나를 골랐을 때 | 길이·시작/끝·편도/순환·구간 목록·지나는 명산·고도 단면·출처 |

명산 모드에서는 산을 고르기 전까지 걷기길 선을 그리지 않는다(전국 축척에 244개 선을 그리면 정상 기호가 묻힌다). 늘 보려면 '걷기길 선 늘 표시'를 켠다.

### 5.2 종류 구분 (빌드 때 분류해 `kind`로 굽는다)

| kind | 판정 규칙(앞에서부터 처음 맞는 것) | 지도 선 | 목록 표기 |
|---|---|---|---|
| **정상 코스로 합침** | 선이 어느 산 정상 150m 안을 지나고 이름에 코스·탐방로가 있음(한라산 성판악 코스, 계룡산 동학사 코스 등) | 정상 코스와 같음 | 그 산 '코스' 탭에 "OSM 노선" 출처로 들어감 |
| 마루금 | 이름에 대간·정맥·기맥 | 갈색 `#6b4e2e` 5px | 마루금 |
| 장거리 걷기길 | `network=nwn/iwn` 또는 이름에 올레·해파랑·남파랑·서해랑·평화누리·코리아둘레 | 남색 `#2c5d9e` 4px | 장거리 |
| 둘레길·자락길 | 둘레길·자락길·순환 | 청록 `#1f7a74` 4px | 둘레길·자락길 |
| 숲길·옛길 | 숲길·옛길·계곡·황톳길·마실길·비렁길, 그 밖 | 청록 3px, 투명도 0.7 | 숲길·옛길 |

공식 탐방로를 별도 종류로 두지 않는다. 정상행 탐방로가 '코스'와 '주변 길' 양쪽에 나오면 지금의 중복 문제가 되살아나기 때문이다.

**색에만 기대지 않는다.** 굵기를 달리하고, 목록에는 색 견본(━) 옆에 **글자 종류명**을 붙인다. 정상 코스는 적갈 `#b4432b` 실선, 계산 경로는 같은 색 점선.

**긴 길**(백두대간 등)은 "이 산 구간"만 진하게, 나머지는 25%로 그린다. superroute가 있으면 걷기길 시트에 구간 목록을 넣는다.

**필터**(걷기길 모드): 종류, 길이(5km 미만·5–10·10 초과), 소요(2시간 미만·2–4·4 초과, '길이로 추정' 표시). 구간은 두루누비를 따른다.

**정직성**: 걷기길 시트마다 "OSM 기여자가 그린 선 · 공식 노선과 다를 수 있음", relation 번호(ODbL), "길이는 선으로 계산"을 표시한다.

### 5.3 데이터 형태

- `walks/index.json`: id·이름·kind·길이·bbox·관련 산(`[{id, dist_km}]`)·전국 축척용 단순화 선(허용 오차 약 200m). 산 시트와 걷기길 모드는 이 파일만으로 그린다.
- `walks/<id>.json`: 원래 선과 구간 정보. 걷기길 시트를 열거나 z≥12일 때 불러온다.

## 7. 설정(기능 토글) 화면

- **여는 곳**: 기록 화면 오른쪽 위, 레이어 패널 끝 '기능 설정 ›', 데스크톱 헤더. 꺼진 기능의 원래 자리(코스 탭 끝 등)에는 "설정에서 켤 수 있음 ›" 한 줄을 남긴다. 레이어 패널의 지도 스위치 3개는 아래 표와 같은 값을 공유한다(같은 설정의 지도 위 바로가기).
- **동작**: 즉시 적용, 저장 버튼 없음(NN/g 토글 지침). 라벨은 켰을 때 생기는 것을 쓴다.
- **저장**: `localStorage['kr100:prefs'] = {"v":1, …}`에 기본값과 다른 항목만 저장하고 try/catch로 감싼다. 바뀌면 `kr100:prefs` 이벤트로 열린 시트를 다시 그린다. 확대 버튼처럼 기기별 값이 맞는 설정이 있어 클라우드 동기화는 하지 않는다.
- **딥링크 우선**: 토글은 입구만 숨긴다. `#/courses`로 들어오면 꺼져 있어도 코스 목록을 연다.

## 8. 시각 언어

**색**: 필드가이드 토큰(`--bg #f7f6f0`, `--text #233c32`, `--accent #315943`, 다크 `--bg #17231e`)을 유지하고, `style.css`의 옛 토큰(radius 14, 그림자, `#2f7d4f`)은 걷어낸다. 강조색은 화면당 주 버튼 1개와 선택 상태에만 쓴다. 선 색 4개는 지도 선과 그 견본에만 쓰고, 다크 모드에서는 명도를 높인 짝(`#e07a5f` 등)을 쓴다.

**타이포**: 시스템 한글 산세리프. 크기 12·13·15·17·20, 굵기 400·600. 세리프 숫자는 기록 화면의 큰 숫자(28px)에만 쓴다. `tabular-nums`, 해발은 "1,708m". 본문 자간 0(지금의 -0.025em은 한글이 답답하다), 줄간격 1.5.

**아이콘**: 인라인 SVG 6개(검색·레이어·내 위치·닫기·뒤로·펼침), 20px, 선 1.5. 아이콘만 있는 버튼은 지도 컨트롤뿐이고 `aria-label`과 툴팁을 단다.

**밀도**: 행 최소 56px, 1px 구분선, 카드 배경·그림자 없음. 시트만 예외로 윗모서리 12px, 1px 윗선, 그림자 `0 -2px 8px rgba(0,0,0,.08)` 하나를 둔다. 칩·버튼 반경 6px.

**문구**: 화면 제목은 명사("내 기록"), 버튼은 동사구 2~6자("길찾기", "GPX 받기"). 정직성 표기는 고정 문구만 쓴다. 검증 '교차검증 일치/자료 간 이견/단일 출처/미검증', 선 '수록 경로/계산 경로/직선 참고 · 등산로 아님', 근거 '공단 안내 확인/자료 선정'. 로딩은 "불러오는 중".

### "AI스럽지 않게" 하기 위한 하지 말 것

1. 이모지와 장식 기호를 쓰지 않는다. 지금 쓰는 ◐ ◎ ⏳ 🎯 🚫 ⚠️ ⛶ ↗ ★ ☆ ✓✓, 파비콘 ⛰️을 모두 SVG 또는 글자로 바꾼다.
2. 그라데이션, `backdrop-filter`(글래스), 흐림 반경 8px을 넘는 그림자를 쓰지 않는다.
3. 슬로건·히어로·소개 문단을 두지 않는다("산으로 가는 나만의 길", "우리 산을 걷는 즐거움", "어디로 떠나볼까요" 삭제).
4. 카드 그리드를 쓰지 않는다. 목록은 행과 구분선으로 만든다.
5. 섹션 설명은 한 줄까지. 그 이상은 '자세히' 접힘에 넣는다(지금 '등산로별 고도'의 4줄 설명 같은 것).
6. 감탄·권유·과장 문구("한눈에", "쉽고 빠르게", "~해보세요!")를 쓰지 않는다.
7. 같은 무게의 버튼을 셋 이상 나란히 두지 않는다. 경로 시트도 [들머리 길찾기](주) + 'GPX 받기'·'따라가기'(글자 버튼)다.
8. 장식용 통계 블록을 두지 않는다(149·4·6·58).
9. 의미 없는 색을 쓰지 않는다. 권역 무지개는 기본 끔이다.
10. 장식 일러스트(등고선 아트)를 쓰지 않는다. 그림은 지도 하나면 된다.
11. "추천 알고리즘"이나 "스마트" 같은 말을 쓰지 않는다. 추천에는 근거를 적는다("인기·계절 기준").

```
┌─────────────────────────────────────────────────────────────────────┐
│ 대한민국 100대 명산                              기록 · 설정 · 원자료 │ 52
├──────────────────────┬──────────────────────────────────────────────┤
│ [검색 ............]  │                                  [레이어]    │
│ [명산│걷기길][필터]   │                                  [내 위치]   │
│ [가까운 순]           │            지도                              │
│ ──────────────────── │                                              │
│ 목록 / 산 / 경로      │                                     [+]      │
│ (시트와 같은 내용,    │                                     [−]      │
│  ‹ 뒤로 헤더)         │                                              │
│ 400px, 스크롤         │                                              │
└──────────────────────┴──────────────────────────────────────────────┘
```

- 시트 내용을 왼쪽 400px 패널에 그대로 넣는다. 같은 모듈이고 단계(detent) 대신 스크롤로 본다. fitBounds의 왼쪽 여백은 0으로 둔다(패널이 지도를 가리지 않으므로).
- 목록 행에 마우스를 올리면 마커를 강조하고, 그 반대도 된다(기존 기능).
- 키보드: `/`는 검색, Esc는 한 단계 위로, Tab 순서는 패널 → 지도 컨트롤 → 지도.
- 경로를 고르면 고도 단면을 패널 안에 둔다. 지도 아래에 띠로 붙이지 않는다(지도 높이를 지키기 위해).
- 640–1023px(태블릿)에서는 바텀시트를 최대 폭 560px로 왼쪽 16px에 띄운다. Material의 바텀시트 최대 폭 640dp를 참고했다.

## 11. 위험·트레이드오프와 구현 순서

### 위험

1. **지도 셸 리팩터링**(main.js, detail.js 808줄): 늦은 응답이 다른 화면의 지도를 건드리는 회귀가 생길 수 있다. 레이어는 `ctx.layers`로만 그려 라우트 전환 때 일괄 삭제하고, `disposed`·`AbortController` 패턴을 시트 단위로 옮긴다.
2. **상세를 시트에 담는 것**: NN/g는 상세 흐름을 시트로 만들지 말라고 경고한다. 상태별 URL, [×], 탭 3개, 상단 바 유지로 대응한다. 그래도 정보 탭이 길면 그 탭만 '전체 페이지로 보기'를 두는 대안을 남긴다.
3. **브라우저 제스처 충돌**(iOS 툴바 높이 변화, 당겨서 새로고침, 스크롤과 드래그의 경합): `dvh`·`overscroll-behavior`, 헤더 드래그 전용, full에서만 내용 스크롤. iOS Safari·삼성 인터넷 실기기로 확인한다.
4. **저작권 표시**: half 이상에서는 시트에 가린다. 시트 안 한 줄로 보완하되, 카카오 로고를 계속 노출해야 하는지는 약관 확인이 필요하다.
5. **걷기길 용량**: index(단순화 선, gzip 150KB 이하 목표)와 개별 파일로 나눈다.
6. **기능이 사라졌다고 느끼는 기존 사용자**: 원래 자리에 한 줄 안내를 남기고 딥링크는 계속 열리게 한다.
7. **홈 추천이 없어진 첫 방문자**: 검색 제안(테마), [가까운 순], '추천 묶음' 토글로 보완한다. 기본은 지도가 직접 말하게 한다.
8. **두 지도 공급자 차이**: MapView 계약에 `dash`·`padding`·저작권 안전 영역을 더하고 공급자별로 구현한다.

### 구현 순서

1. **기반**: `prefs.js`, `#/settings`, SVG 아이콘, 이모지 제거, 옛 토큰 정리(토글을 받을 그릇을 먼저 만든다).
2. **지도 셸 + 목록 시트**: 상주 MapView, `sheet.js`(단계·제스처·키보드), 검색·칩, 필터·레이어 모달, `#/`=`#/map`, `#/courses` 리다이렉트, 탭바 제거.
3. **산·경로 시트**: 코스 행 통합(trail_index), 선 소스 우선순위, 고도 단면, 길찾기, GPX 받기. 옛 상세 기능은 토글 뒤로 옮긴다.
4. **걷기길**: 빌드 스크립트(relation과 이름 붙은 길 → kind → index·개별 파일), '주변 길' 탭, 걷기길 모드·시트.
5. **기록·데스크톱 정리 후 점검**: 공급자 2 × 라이트/다크 × 키보드·스크린리더, 390px·1280px 캡처 비교.
