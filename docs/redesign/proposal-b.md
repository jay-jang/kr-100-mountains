# 대한민국 100대 명산 — 모바일 지도 중심 재설계 제안

**첫 화면을 지도로 통합하고, 산과 걷기길을 같은 지도에서 선택하도록 바꾼다.** 하단 메뉴는 **지도·내 기록** 두 개로 줄인다. 산 상세의 등산로·대표 코스·고도·GPX는 **‘경로 선택’ 한곳**에서 연결한다. 경로 조합과 파일 도구는 기본 화면에서 접고, 설정에서 켤 수 있게 한다.

## 1. 핵심 원칙

1. 첫 방문에도 검색·목록 전환 없이 지도가 보인다.
2. 산과 걷기길을 동등한 탐색 대상으로 다루되, 정상 등정과 걷기 완료는 구분한다.
3. 경로를 선택하면 지도·거리·고도·출처가 같은 선택을 따른다.
4. 자주 쓰는 조작은 보이고, 고급 도구는 사용자가 켠다.
5. 계산·자료 부족·검증 수준은 선택한 경로 가까이에 표시한다.

## 2. 현재 상태와 설계 근거

BRIEF 전체, `src/views/*.js`, 지도·검색·기록·경로 관련 모듈, 두 CSS, 데이터와 화면 캡처를 직접 확인했다. 아래는 스냅샷에 대한 판단이며, 실제 이용자 관찰이나 성능 측정 결과는 아니다.

| 확인한 상태 | 설계에 반영할 점 |
|---|---|
| `explore.js`의 초기값은 `data-view="list"`이며 모바일 지도를 숨긴다. | 기본값만 변경하는 데서 끝내지 않고 목록을 지도 위 시트로 재구성한다. |
| 홈 전체 캡처는 4,423px이며 실제 지도가 없다. | 추천·지역·목록별 진입을 지도 검색과 조건으로 합친다. |
| 상세는 지도가 먼저 나오지만 전체 4,418px이고 지도 안에 버튼 네 개가 배치된다. | 지도 우선 배치는 유지하고 도구를 선택 경로에 종속시킨다. |
| 대표 코스는 304개를 일괄 렌더링하며 전체 캡처가 68,724px이다. | 전체 카탈로그는 유지하되 검색·분할 표시로 탐색한다. |
| 데이터는 149산·504등산로·304대표 코스다. 대표 코스에는 좌표 선형이 없는 항목도 있다. | 코스 설명과 표시 가능한 경로를 무리하게 동일시하지 않는다. |
| `routegpx.js`에는 이미 OSM 도보 relation을 받는 통로가 있다. | 주변 걷기길을 기존 통로와 연결하되 생성 방식 구분을 보강한다. |
| `navInfo()`는 최고 고도 지점을 남은 거리 기준으로 삼는다. | 트레킹에서는 선택한 도착점·방향을 기준으로 바꾼다. |

GPX 721개와 신규 OSM 경로 약 244개는 **BRIEF 제공 수치**다. 신규 경로의 최종 개수·선형·공식 운영 정보는 **미확인**이다.

## 3. 정보구조·내비게이션

하단에는 목적이 분명한 두 탭만 둔다. 지도 안의 **산 / 걷기길**은 탐색 대상 전환이며 별도 페이지 탭이 아니다. 설정은 상단의 고정 버튼으로 연다.

| 현재 | 변경 |
|---|---|
| 산 둘러보기 `#/` | 지도 첫 화면으로 통합 |
| 명산 지도 `#/map` | 검색·산·걷기길·목록을 포함한 기본 화면 |
| 대표 코스 `#/courses` | 지도 화면의 ‘대표 코스 모음’; 독립 하단 탭 제거 |
| 산 상세 `#/m/<id>` | 지도와 상세 시트를 함께 표시 |
| 내 기록 `#/track` | 기록 목록 우선; 진행률·백업은 접힘 |
| 테마 버튼 | 설정의 시스템/라이트/다크 선택 |
| 없음 | `#/settings`, 걷기길 상세 `#/walk/<stableId>` |

**기존 링크 처리**

- `#/`는 `replaceState`로 지도에 연결한다. 남아 있는 검색 매개변수도 전달한다.
- `#/map`의 `region,list,all,q,hiked,sort,easy,hours,distance,focus`를 모두 보존한다. 목록 선택은 기존 합집합, 코스 조건은 기존의 동일 코스 충족 의미를 유지한다.
- `#/m/<id>?course=<courseId>`는 해당 코스를 선택한다. 정확히 대응하는 선형이 있을 때만 표시한다.
- `#/courses?q=&region=`는 기존 대표 코스 검색 범위를 유지한 채 전체 목록 시트를 연다. 일반 산 검색으로 의미를 바꾸지 않는다.
- `#/stats`는 `#/track`의 별칭으로 유지한다.
- 돌아가기는 전체 검색 URL·지도 범위·선택·목록 스크롤을 복원한다. 외부에서 직접 들어온 상세의 복귀점은 지도다.
- 검색으로 조건 밖의 산을 선택하면 **‘현재 조건 밖의 산’**으로 임시 표시한다. 조건을 몰래 해제하지 않는다.

## 5. 지도 상호작용

### 시트 단계와 제스처

| 단계 | 높이 | 844px 화면의 상단 | 용도 |
|---|---:|---:|---|
| peek | 160px | 628px | 첫 화면·상세 진입 |
| half | 352px | 436px | 산 요약·경로 선택 |
| full | 708px | 80px | 전체 목록·긴 설명 |
| 지도 집중 | 44px | 744px | 시트를 접고 지도 보기 |

하단 탭 높이는 56px다. 다른 화면에서는 `100dvh`와 안전영역으로 다시 계산한다. 첫 화면은 검색 아래 약 500px의 지도 공간을 확보한다.

탐색 시트는 지도를 함께 조작할 수 있는 비모달로 만든다. 조건·레이어·날짜 입력은 별도 모달로 열고 배경 조작을 막는다. 이러한 구분은 [Material 공식 Bottom sheets 문서](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomSheet.md)의 standard/modal 패턴을 따른다.

- 시트 드래그는 상단 44px 손잡이 영역에서만 시작한다. 본문은 일반 스크롤로 두어 지도 이동과 충돌을 줄인다.
- ‘펼치기·접기·닫기’를 항상 제공한다. 키보드와 보조기술도 같은 상태를 선택한다.
- full에서는 지도 검색·컨트롤을 감추고 시트 안에 검색을 둔다.
- 뒤로가기는 열린 모달부터 닫고, 다음으로 항목 선택을 해제하거나 이전 라우트로 돌아간다. 시트 높이 변경마다 방문 기록을 쌓지 않는다.
- 검색 키보드가 열리면 가시 뷰포트에 맞춰 검색 결과를 표시한다. 한글 조합 중 Enter는 선택·제출하지 않는다.
- 드래그 대체 버튼과 지도 이동 방향 버튼을 제공한다. 이는 [W3C 드래그 동작 지침](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)의 취지에 맞는다.

### 컨트롤과 검색

지도 오른쪽 아래에 **레이어·내 위치** 44px 버튼을 두고 시트 위 12px 이상 떨어뜨린다. 줌 버튼도 같은 묶음에서 접근한다. 공급자 로고·저작권은 시트 바로 위 전용 공간에 보이게 한다.

검색은 상단 한곳, 조건은 검색 옆, 정렬은 목록 시트 안에 둔다. 적용 조건은 해제 가능한 토큰으로 보여준다. 지도 이동만으로 목록을 계속 바꾸지 않고 **‘이 영역에서 찾기’**를 제공한다. 지도 범위에서 경로를 찾는 패턴은 [komoot 공식 탐색 문서](https://support.komoot.com/hc/en-us/articles/10207999797530-Find-routes-and-inspiration-on-komoot)에서 확인했다.

내 위치는 기본적으로 한 번 측정한다. 지속 추적은 사용자가 별도로 시작하며, 종료·라우트 이탈 때 중단한다. 위치 거부 시 지역 검색과 목록은 계속 사용할 수 있다.

### 경로를 띄우는 단일 진입점

**‘경로 선택’ → 경로 행 선택 → 지도 표시**를 유일한 흐름으로 둔다. 선을 눌러도 같은 선택 상태와 같은 경로 상세를 연다.

1. 선택 경로를 굵게 표시하고 시작·끝을 보여준다.
2. 같은 시트에서 자료 거리, 선형 거리, 시간, 난이도·검증 상태를 읽는다.
3. 고도·출처·길찾기를 해당 경로 안에서 펼친다.
4. GPX·비교·조합은 기능을 켠 경우에만 추가한다.

선 재탭으로 경로를 갑자기 흐리게 만들지 않는다. 해제는 명시적인 버튼으로 한다. 겹친 선은 경로명 선택 목록을 열며, 색상 외에 이름과 선택 표시로 구별한다.

## 6. 주변 하이킹·트레킹 경로

**지도 레이어·산 상세·전국 목록이 같은 경로 데이터를 참조한다.** 산에 연결되지 않은 길도 전국 검색에서 찾을 수 있어야 한다.

| 종류 | 지도 표현 | 목록 정보 |
|---|---|---|
| 둘레길·자락길 | 청록 선 | 구간명·길이·순환 여부 |
| 장거리 걷기길 | 청록 선과 구간 표식 | 전체 길과 개별 구간 구분 |
| 종주 마루금 | 갈색 선 | 방향·장거리 표시 |
| 숲길·계곡길 | 청록 선 | 시작·끝·길이 |
| 탐방로 | 녹색 선 | 목적지·공식 안내 여부 |

선택 경로는 종류와 관계없이 가장 굵게 표시한다. **‘공식’은 색이나 이름에서 추정하지 않고 별도 근거가 있을 때만 표시한다.**

산 상세의 주변 범위는 **정상과 선 사이 최단 직선거리 10km**를 초기 설계값으로 두고 5/10/20km로 바꿀 수 있게 한다. 실제 접근성과 일치하는지는 데이터 검토 후 조정한다. 거리에는 접근 도로·이동 시간이 포함되지 않음을 명시한다.

장거리 relation은 주변 통과 구간을 먼저 보여주고 전체 보기로 확장한다. 전체 길이와 표시 구간 길이는 따로 표기하며, 화면에서 잘린 구간을 완주 코스로 다운로드하지 않는다.

데이터에는 안정적인 ID, 상위 길·구간 관계, 다중 선형, 길이 범위, 시작·끝, 출처, 수집·확인일, 검증 수준, 생성 방식을 보존한다. 계산 경로·OSM 등록 선형·사용자 GPX를 분리하며 **GPX 파일이라는 이유만으로 실측이라고 부르지 않는다.**

동일 길의 산별 중복 연결은 ID로 합치고, 같은 이름의 다른 길은 지역·구간명으로 구별한다. 시간·난이도 미상은 ‘미확인’으로 표시한다. 자료가 없을 때는 **‘수록된 경로 없음’**으로 안내한다.

## 8. 설정과 저장

지도 기본 표시 두 항목은 ON, 추가 도구 일곱 항목은 OFF다. 화면 모드는 시스템, 배경지도는 일반지도가 기본이다. 기존 사용자의 테마·지도 종류·동기화 선택은 이어받는다.

설정은 버전이 있는 `localStorage`에 저장한다. 기존 `kr100:hiked`, 테마, 지도 종류, 계획 키를 보존하며 탐색 위치·시트 높이는 `sessionStorage`로 분리한다. 저장 실패 시 현재 세션에서 적용하고 저장되지 않았음을 알린다.

경로 화면의 **‘GPX 도구 켜기’**도 같은 설정을 변경한다. OFF 전환은 도구와 작업을 중단하되 자료를 삭제하지 않는다. 브라우저 위치 권한은 앱 토글로 승인할 수 없으며, 저장 위치 삭제와 분리한다.

출처·계산 표시·검증·현장 제한 정보는 토글 대상에서 제외한다.

## 9. 시각 언어

기존 종이색과 짙은 녹색은 유지하되, 지도 밖의 장식과 세리프 큰 숫자는 줄인다.

| 요소 | 규칙 |
|---|---|
| 색 | 라이트 배경 `#F7F6F0`, 표면 `#FFFEF9`, 본문 `#233C32`, 강조 `#315943`; 다크는 기존 녹색 계열 유지 |
| 글자 | 시스템 한글 고딕; 입력·본문 16px, 제목 20px, 보조 13–14px |
| 숫자 | 거리·시간은 고정폭 숫자, 해발보다 경로 판단 정보 우선 |
| 아이콘 | 일관된 단색 SVG; 주요 기능은 텍스트 병기 |
| 밀도 | 좌우 16px, 간격 8px 기준, 목록 행 72–88px |
| 조작 | 최소 44×44px, 검색·주요 버튼 48px |
| 표면 | 목록은 구분선, 시트 상단 모서리 12px, 그림자는 지도 위 경계에만 최소 사용 |
| 문구 | ‘경로 선택’, ‘시작점 길찾기’, ‘자료 없음’, ‘계산 경로’처럼 동작·상태 중심 |

44px은 이 제품의 기준이다. WCAG 2.2 AA의 최소 타깃 규정은 예외 조건을 포함한 24px 기준이므로 둘을 혼동하지 않는다. [W3C 타깃 크기 지침](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

**사용하지 않을 것:** 그라데이션 히어로, 글래스모피즘, 기능별 이모지, 반짝임, 반복되는 큰 카드 그림자, “나만의 길” 같은 홍보 문구, 근거 없는 추천·인기 배지, 색상만으로 난이도·검증을 구분하는 표현.

다크 모드에서도 선과 본문 대비를 확인한다. 현재 Kakao 공급자는 다크 지도 전환을 구현하지 않았으므로 어두운 앱 표면과 밝은 배경지도의 조합을 지원한다. 지도 전체 색 반전은 적용하지 않는다.

## 10. 데스크톱·구현 순서·검수

**≥1024px:** 왼쪽 360–400px 탐색 패널과 오른쪽 지도를 배치한다. 모바일 시트 내용은 같은 패널에서 보여주며 상세용 두 번째 지도를 만들지 않는다. 기록·설정은 읽기 적합한 폭으로 제한한다.

| 순서 | 구현 범위 | 완료 판단 |
|---|---|---|
| 1 | `main.js` 라우트 호환, 지도 기본 화면, 두 탭, 설정 | 모든 기존 링크·복귀 조건 유지 |
| 2 | `explore.js` 공용 시트·선택 상태·지도 집중 보기 | 390×844 첫 화면에 지도 노출, 버튼으로 단계 전환 |
| 3 | 등산로·대표 코스·GPX 연결 모델 | 정확한 대응과 선형 없음 구분 |
| 4 | 상세 경로 선택 통합·주변 걷기길 | 한 선택이 지도·고도·출처를 함께 변경 |
| 5 | 고급 도구·걷기 기록·기존 데이터 이전 | OFF 상태에서도 자료 보존 |
| 6 | 양 공급자·라이트/다크·접근성 검수 | 실제 조작과 실패 경로 검증 |

Vite·바닐라 JS·`el()`을 유지한다. CSS는 공용 토큰·지도·시트·기록 규칙으로 정리하여 현재 두 파일의 누적 덮어쓰기를 줄인다.

지도 추상화에는 범위 조회·이동 완료 이벤트·시트 가림 영역을 고려한 화면 맞춤·공용 줌/이동 조작을 추가한다. 점선 표현을 사용하려면 두 공급자 모두 지원하도록 계약을 확장한다. 지도 크기 변화 후 `relayout()`을 호출하고 현재의 `disposed`·라우트 버전 보호를 유지한다.

걷기길은 빌드 시 인덱스와 지역별 선형을 생성해 필요한 부분만 받는다. 기본 탐색을 실시간 Overpass 응답에 의존시키지 않는다. 걷기 기록은 별도 저장소로 시작하며 기존 산별 단일 날짜와 백업을 보존한다. 외부 동기화는 현재 지원하는 등정 범위를 명시한다.

구현 후 기존 UX·코스·계획·경로·선택 검사를 실행하고, 320/390/768/1024px 이상에서 양 지도 공급자를 확인한다. 지도 실패, 늦은 응답, 위치 거부, IME, 키보드, 200% 글자 확대, 잘못된 백업, 끊긴 선형도 포함한다. **이번 제안 작업에서는 빌드·테스트를 실행하지 않았고 파일을 생성하거나 수정하지 않았다.**
