# 대한민국 100대 명산 웹앱 UI 재설계 제안서

---

## 1. 핵심 원칙

1. **지도가 곧 홈(Map-First Canvas)**: 앱 진입 즉시 100% 뷰포트의 전국 명산 지도가 열리며, 모든 탐색은 지도 위 바텀시트에서 시작된다.
2. **단일 조작 경로(Single Trail Entry Point)**: 산 상세에서 지도로 경로를 올리는 분산된 4개의 진입로를 단 하나의 '경로 선택기'로 통합한다.
3. **봉우리 너머의 길(Peak & Trails Integration)**: 정상 등정로에 국한되지 않고 둘레길·자락길·종주 마루금을 지도 레이어와 상세 정보에 동등한 탐색 축으로 편입한다.
4. **산악 수첩의 정직성(Field Guide Authenticity)**: AI 특유의 과장된 카드와 미사여구를 배제하고, 실측과 계산 데이터를 투명하게 구분하는 활자 중심의 정갈한 필드 가이드 톤을 계승한다.
5. **목적 중심의 가벼움(Progressive Disclosure & Settings)**: 다중 GPX, 경로 계획기, Overpass 실시간 호출 등 전문 기능은 '설정(기본 OFF)'으로 격리하여 모바일 첫 사용성을 극대화한다.

## 2. 정보구조 및 내비게이션 (IA & Navigation)

### 2.1 탭 및 라우트 구조 개편
기존의 4개 하단 탭(`산 둘러보기 #/`, `명산 지도 #/map`, `대표 코스 #/courses`, `내 기록 #/track`) 체제는 모바일에서 탐색 동선이 분산되고 지도 접근을 방해했습니다. 이를 **3개 탭(지도 탐색 · 내 기록 · 설정)**으로 압축합니다.

```
[앱 진입: #/ 또는 #/map] (전체화면 명산 지도 + 3단계 바텀시트)
  ├── 탭 1: 지도 탐색 (기본 홈, #/ 및 #/map 통합)
  │     ├── 바텀시트 Peek: 퀵 검색바 + 근접 명산 요약
  │     ├── 바텀시트 Half: 검색 결과 목록 / 둘레길 칩 / 필터
  │     └── 바텀시트 Full: 전체 149개 명산 목록 및 정렬
  ├── 산 상세 (#/m/<id>)
  │     ├── 지도 뷰포트 (상단 고정/가변)
  │     ├── 단일 경로 선택 바 (대표코스 / 등산로 / 주변 둘레길)
  │     └── 컨텍스트 바텀시트 (개요, 교통, 후기, 출처)
  ├── 탭 2: 내 기록 (#/track)
  │     ├── 100대 명산 진행률 현황판
  │     └── 산행 기록 타임라인 및 백업
  └── 탭 3: 설정 (#/settings)
        └── 기능 켜기/끄기 토글 (경로 계획기, 범례, GPX 도구 등)
```

### 2.3 기존 딥링크 처리 (하위 호환성 100% 보장)
- `#/`: `#/map`과 동일하게 지도 중심 탐색 화면 렌더링.
- `#/map?region=강원&list=bac&q=설악&hiked=1&sort=near&easy=1&hours=4&distance=5&focus=<id>`:
  기존 쿼리 파라미터를 그대로 파싱하여 지도의 포커스 좌표 이동 및 바텀시트의 필터 토큰에 즉시 반영.
- `#/courses?q=&region=`:
  `#/map?q=&region=&filter=course`로 내부 리다이렉트하여 지도 상에서 해당 코스를 가진 산들을 즉시 하이라이트.
- `#/m/<id>`: 해당 산 상세 화면으로 직행하며, 상단에 `← 지도` 뒤로가기 버튼 유지.
- `#/m/<id>?course=<courseId>`: 상세 화면 진입과 동시에 단일 경로 선택기에서 지정된 `<courseId>`를 자동 활성화하여 지도에 폴리라인 표시.
- `#/stats`: `#/track`으로 자동 정규화.

## 4. 지도 상호작용 상세 설계

### 4.1 바텀시트 3단계 높이 및 제스처 상태 머신
바닐라 JS 기반으로 브라우저 리플로우를 최소화하는 CSS `transform: translateY()` 구조를 적용합니다.

```
+---------------------------------------+ 화면 상단
|  상단 48px 여백 (안전 영역)           |
+=======================================+ <-- Full (90vh, ~760px)
|  전체 목록 스크롤, 상세 필터 패널     |
|                                       |
+=======================================+ <-- Half (48vh, ~405px)
|  검색 결과, 산 요약, 코스 카드        |
|                                       |
+=======================================+ <-- Peek (~110px)
|  핸들 + 퀵 검색창 + 활성 필터 칩      |
+=======================================+ 하단 탭바 (56px)
```

1. **Peek (최소 접힘, 높이 약 110px)**:
   - 노출 요소: 상단 드래그 핸들(32×4px, 라운드) + 퀵 검색창 + 가로 스크롤 필터 칩.
   - 지도 노출 면적: 화면 높이의 80% 이상. 지도를 자유롭게 이동/확대하며 핀을 탐색하는 기본 상태.
2. **Half (절반 펼침, 높이 약 48vh / 405px)**:
   - 트리거: 지도 핀 탭, 검색어 입력 시작, 또는 Peek 핸들을 위로 드래그.
   - 노출 요소: 선택된 산의 요약 카드(이름, 해발, 거리, 등정 버튼, 주요 코스 3개) 또는 검색 결과 리스트(5~6개).
   - 지도와 목록이 5:5로 공존하여 시각적 맥락을 유지.
3. **Full (완전 펼침, 상단 48px 여백 / 약 90vh)**:
   - 트리거: Half에서 위로 드래그, 또는 '전체 목록 보기' 탭.
   - 노출 요소: 149개 산 전체 정렬 목록(스크롤 가능), 세부 필터 조건식, 초기화 버튼.
   - 제스처 충돌 방지: 시트 내부 스크롤이 `scrollTop === 0`일 때만 아래 드래그 제스처로 Half/Peek으로 내려가며, 스크롤 도중에는 시트가 닫히지 않음.

### 4.2 엄지 영역(Thumb Zone) 지도 컨트롤 배치
한 손 조작성(Ergonomics)을 위해 주요 지도 조작계를 우측 하단 엄지 도달 범위에 집결합니다.
- **[◎ 현위치 버튼]** (48×48px, 터치 타깃 충분): 바텀시트 상단 바로 위, 우측 여백 16px에 플로팅 배치. 1회 탭 시 내 위치로 지도 이동(`flyTo`), 2회 탭 시 나침반 추적 모드.
- **[≡ 레이어 버튼]** (44×44px): 현위치 버튼 바로 위에 배치. 탭 시 팝오버로 `[지형도 / 일반지도 / 위성]`, `[✓ 주변 트레킹 경로]`, `[✓ 등정한 산 강조]` 선택.
- **[± 줌 컨트롤]**: 기본 화면에서는 제거(핀치 제스처 권장). 손가락 조작이 어려운 사용자를 위해 [설정 > 화면 내 줌 버튼 표시]에서 켤 수 있도록 분리.

### 4.3 산 상세에서 경로를 지도에 올리는 단일 진입점 설계
현재 `src/views/detail.js`의 가장 치명적인 문제는 경로를 지도에 띄우는 버튼이 4군데로 쪼개져 있다는 점입니다. 이를 **단 하나의 고정 경로 선택 바(Single Route Selector)**로 전면 일원화합니다.

```
+-------------------------------------------------------------+
| ▾ 코스 선택: [ 1. 관청리-중봉 코스 (왕복 7h · 보통)      ] |
+-------------------------------------------------------------+
| [요약] 거리 8.0km | 상승 1,020m | 계산경로 배지 | [GPX 다운] |
+-------------------------------------------------------------+
```
- **작동 방식**:
  - 드롭다운/세그먼트를 누르면 해당 산의 모든 경로가 카테고리별로 단일 리스트로 제공됩니다:
    - `── 대표 등산로 ──` : 1. 관청리 코스, 2. 화악터널 코스
    - `── 주변 트레킹 ──` : 3. [둘레길] 화악산 자락길, 4. [종주] 한북정맥 마루금
    - `── 경로 해제 ──` : 지도에서 선 지우기
  - 항목을 선택하는 순간:
    1. 지도가 해당 경로의 전체 바운드(`fitBounds`)로 부드럽게 이동.
    2. 지도 위에 트랙 폴리라인(파랑: 등산로 / 초록: 둘레길 / 보라: 마루금) 표시.
    3. 들머리(S) 및 정상(G) 마커가 생성됨.
    4. 선택 바 바로 아래에 미니 고도 프로파일 스파크라인과 [GPX 저장] 단일 버튼 노출.
- **기존 지도 하단 버튼 4개 정리**:
  - `내 위치`: 우측 하단 공용 플로팅 버튼으로 흡수.
  - `길찾기`: 상세 화면의 교통 섹션 들머리 주소 옆 `[카카오맵 ↗]` `[네이버지도 ↗]` 외부 링크로 이동.
  - `GPX 여러 개 불러오기` & `경로 따라가기`: 설정에서 활성화한 경우에만 서브 메뉴로 노출.

## 5. 주변 하이킹·트레킹 경로 설계

### 5.1 데이터 노출 위치 및 체계
OSM의 `route=hiking|foot` relation(전국 244개 둘레길·올레·마루금 등)과 산 반경 매핑 데이터를 3개 영역에 유기적으로 배치합니다.

1. **지도 캔버스 오버레이 (레이어 연동)**:
   - 우측 레이어 메뉴에서 '주변 트레킹 경로'가 켜져 있으면, 100대 명산 주변의 둘레길·마루금이 배경 지도 위에 가벼운 선으로 상시 노출됩니다.
   - 경로 선을 탭하면 바텀시트가 열리며 해당 트레킹 경로의 명칭, 총 거리, 주요 경유지 팝업 노출.
2. **산 상세 화면의 [주변 트레킹] 전용 섹션**:
   - 기존의 불필요하게 길었던 '대표 코스' 목록을 정상 등정로와 주변 트레킹으로 재편.
   - 정상 등정을 원치 않거나 가벼운 트레킹을 원하는 사용자를 위해, 해당 산을 지나는 둘레길 구간(예: 지리산둘레길 3코스, 북한산둘레길 1~21구간)을 독립 카드로 표시하고 즉시 `[지도에 올리기]` 지원.
3. **바텀시트 검색 및 필터 칩**:
   - `[둘레길 있는 산]`, `[종주 마루금 연계]` 필터 칩을 제공하여, 정상 등정 외 트레킹 목적의 산 탐색을 1초 만에 수행.

### 5.2 경로 종류 구분 및 시각적 위계 (Visual Hierarchy)
모바일 작은 화면에서 선들이 엉키지 않도록 선 스타일, 두께, 색상을 명확히 분리합니다.

| 경로 구분 | 선 스타일 및 색상 | 지도 라벨 표기 | 의미 및 대상 |
|---|---|---|---|
| **정상 등산로** | 실선 4px, 군청색 (`#1d4ed8`) | `▲ 정상 등산로` | 들머리에서 정상으로 향하는 핵심 코스 |
| **둘레길·자락길** | 실선 3px, 포레스트 그린 (`#2d6a4f`) | `⟲ 둘레길` | 산 자락을 완만하게 도는 순환·트레킹 코스 |
| **장거리 걷기길** | 일점쇄선 3px, 주황색 (`#d97706`) | `⚑ 걷기길` | 제주올레, 해파랑길, 평화누리길 등 장거리 도보길 |
| **종주 마루금** | 대시선 2.5px, 보라색 (`#7c3aed`) | `▲ 마루금` | 백두대간, 낙동정맥 등 능선 마루금 잇기 |

*정직성 원칙 적용*: OSM 라우팅 엔진으로 추출한 계산 경로는 경로명 옆에 회색 폰트로 `[계산]` 태그를 표기하고, 국립공원공단 등 공인 검증 코스는 녹색 `[공식]` 태그를 병기하여 사용자의 혼선을 원천 차단합니다.

## 7. 설정(기능 토글) 화면 설계

### 7.1 구조 및 저장 방식
- **진입 경로**: 헤더 우측 상단 `[⚙]` 아이콘 또는 하단 내비게이션 3번째 탭 `[설정]`.
- **저장 메커니즘**: `localStorage`의 `kr100:settings` 키에 단일 JSON 객체로 영구 저장. 별도 로그인 없이 즉시 브라우저에 반영되며 정적 호스팅(GitHub Pages) 제약에 완벽 부합.

### 7.2 설정 항목 및 기본값 정의
```javascript
// localStorage["kr100:settings"] 스키마 및 기본값
{
  "showTrekRoutes": true,       // 주변 하이킹·트레킹(둘레길·마루금) 레이어 노출 (기본 ON)
  "showMapLegend": false,       // 지도 좌하단 고정 범례 표시 (기본 OFF, 공간 절약)
  "showZoomButtons": false,     // 지도 화면 내 ± 줌 버튼 표시 (기본 OFF, 핀치 권장)
  "defaultMapType": "terrain",  // 기본 지도 스타일: terrain(지형도) / normal(일반)
  "enableRoutePlanner": false,  // 산 상세: 경로 조합 계획기 노출 (기본 OFF)
  "enableMultiGpx": false,      // 산 상세: 로컬 GPX 중첩 불러오기 (기본 OFF)
  "enableLiveTracking": false,  // 산 상세: 실시간 경로 따라가기 내비 (기본 OFF)
  "enableOsmLiveFetch": false,  // 산 상세: OSM Overpass 실시간 네트워크 로드 (기본 OFF)
  "theme": "system"             // system / light / dark
}
```

## 8. 시각 언어 (Visual Language) 및 "AI스럽지 않게" 만드는 구체 규칙

현재의 `src/fieldguide.css`가 지닌 단아한 '인쇄물 산악 수첩(Field Guide)' 감성을 극대화하고, 시중의 양산형 AI 웹앱 느낌을 완벽히 차단합니다.

### 8.1 구체 규칙 및 "절대 하지 말 것" 목록
1. **무지개빛 그라데이션 및 글래스모피즘 전면 금지**:
   - `background: linear-gradient(...)`나 과도한 `backdrop-filter: blur(...)` 금지.
   - 종이 질감의 솔리드 캔버스(`--bg: #f7f6f0`, `--bg-elev: #fffef9`)와 먹색 1px 구분선(`border: 1px solid #dddfd3`)으로 엄정한 구조미를 형성한다.
2. **이모지 아이콘 및 반짝이(✨) 남발 금지**:
   - 🚀, 🔥, 💡, ✨, 🌟 같은 감정 과잉 아이콘 일체 배제.
   - 지도와 현장에서 검증된 단정한 기호(`▲`, `◎`, `⟲`, `⚑`, `★`, `↓`, `↗`)만 허용한다.
3. **공허한 마케팅 수식어구 배제**:
   - "나만의 산을 찾아 떠나보세요", "AI가 추천하는 최고의 힐링 코스" 등 주관적 미사여구 금지.
   - "해발 1,708m · 관청리 들머리 · 왕복 7시간 · 계산 경로(OSM)"처럼 객관적 산악 사실만 간결하게 기술한다.
4. **거대한 부유형 그림자(Drop Shadow) 카드 금지**:
   - 붕 떠 있는 카드 대신 국립공원 안내 책자 스타일의 괘선 기반 리스트와 표(Table) 레이아웃 적용.
5. **활자(Typography) 체계의 정직한 규율**:
   - 숫자는 세리프 및 타뷸라 폰트(`font-variant-numeric: tabular-nums; font-family: Georgia, serif;`)를 적용하여 고도, 거리, 소요 시간의 비교 가독성을 극대화한다.
6. **자연의 잉크톤 팔레트 유지**:
   - 침엽수 녹색(`--accent: #315943`), 짙은 쑥색(`--text: #233c32`), 모래색(`--bg-soft: #eeeee5`). 인공적인 원색 네온 컬러 사용 금지.

## 9. 데스크톱 (≥1024px) 대응

모바일의 3단계 바텀시트 인터랙션은 데스크톱 화면에서 **스플릿 뷰(2-Pane Layout)**로 자연스럽게 확장됩니다.

```
+-----------------------------------------------------------------------------------+ [1440x900]
|  [山] 대한민국 100대 명산       [지도탐색]  [대표코스]  [내기록]  [설정]       ◐  | 상단 글로벌 바
+------------------------------------+----------------------------------------------+
| [🔍 산 이름·지역 검색            ] |                                              |
| [전국 ▾] [4대공통] [둘레길] [쉬움] |              ▲ 설악산                        |
| 149개 명산 목록       [가까운 순 ▾]|                                              |
|------------------------------------|                                              |
| ■ 설악산 (1,708m) · 강원 속초      |                      ▲ 오대산                |
|   오색 코스 · 왕복 8h · 어려움     |                                              |
|   주변 트레킹: 설악산 자락길       |                                              | 우측 가변 뷰포트
|------------------------------------|   ▲ 치악산                                   | 풀스크린 지도
| ■ 치악산 (1,282m) · 강원 원주      |                                              |
|   사다리병창 코스 · 왕복 5h · 보통 |                                              |
|------------------------------------|                                [ 레이어 ≡ ]  |
| 좌측 고정 패널 (폭 400px, 독립스크롤) |                                [  ◎ 현위치 ] |
+------------------------------------+----------------------------------------------+
```
- **좌측 고정 패널 (폭 400px)**: 모바일 바텀시트의 모든 내용(검색창, 필터, 정렬, 산 목록, 상세 정보)이 독립적으로 스크롤되는 사이드바로 전환.
- **우측 지도 뷰포트 (가변 잔여 영역)**: 화면 전체에 지도가 상시 렌더링되며 마커 클릭 시 좌측 패널이 즉시 해당 산의 상세 정보로 전환.
- **키보드 접근성**: `/` 키로 검색창 포커스, `Esc` 키로 상세 닫기, 한국어 IME 조합 완료 후 검색어 반영(`e.isComposing` 방어 유지).

## 11. 위험·트레이드오프 및 구현 로드맵

### 11.1 기술적 위험 및 해결 방안
1. **바닐라 JS 바텀시트 제스처 구현 복잡도**:
   - 위험: 시트 내부 목록 스크롤과 시트 드래그 제스처가 충돌하여 오작동 발생 가능.
   - 해결: CSS `touch-action: pan-y`를 지정하고, 터치 이벤트 리스너에서 `sheet.scrollTop === 0`일 때만 translateY 드래그를 허용하며 관성 스크롤 종료 후 임계값(Threshold 20%)에 따라 snap animation 적용.
2. **244개 주변 트레킹 경로 데이터 용량 증가**:
   - 위험: OSM relation 지오메트리를 통째로 번들링할 경우 초기 JSON 크기가 커져 로딩 지연.
   - 해결: Ramer-Douglas-Peucker 알고리즘으로 오차 10m 이내로 좌표를 단순화(simplify)하고, 전국 통합 번들 대신 권역별/산별 매니페스트로 분할하여 필요 시 온디맨드 로드.
3. **Leaflet 및 Kakao 공급자 추상화 일관성**:
   - 위험: 두 지도 엔진 간 폴리라인 스타일, 툴팁, fitBounds 동작의 차이로 경로 표시가 어긋날 위험.
   - 해결: `src/map.js`에 `drawTrailRoute(geometry, style)`, `clearTrailRoutes()`의 공통 인터페이스를 정의하여 공급자 내부 코드와 뷰 로직을 철저히 격리.

### 11.2 단계별 구현 로드맵
- **1단계: 메인 뷰 단일화 및 지도 바텀시트 구축 (기반 작업)**
  - `home.js`와 `explore.js` 통합, 바닐라 JS 바텀시트 컴포넌트(`src/bottomsheet.js`) 신설.
  - 모바일 진입 시 지도가 100% 뜨고 바텀시트가 Peek(110px) 상태로 연동되도록 라우터 개편.
- **2단계: 산 상세(`detail.js`) 단일 경로 선택기 도입**
  - 기존의 분산된 4개 경로 진입로 제거 및 상단 단일 드롭다운 바 구축.
  - 지도 하단 버튼 4개 정리(현위치는 공용 버튼으로, 길찾기는 교통 링크로 이동).
- **3단계: 주변 하이킹·트레킹 데이터 파이프라인 및 레이어 결합**
  - OSM relation 기반 둘레길/마루금 GeoJSON 빌드 및 스타일 분기(둘레길 녹색, 마루금 보라색).
  - 산 상세에 [주변 트레킹] 섹션 추가 및 지도 레이어 토글 연동.
- **4단계: 설정 화면(`settings.js`) 및 기능 토글 분리**
  - 경로 계획기, GPX 다중 로드, 실시간 내비, Overpass 호출을 설정 화면으로 격리하고 `localStorage` 상태 연동.
- **5단계: 접근성 및 반응형 완성도 검증**
  - 모바일 44px 이상 터치 타깃, 다크모드 색상 대비, 데스크톱 2-패널 스플릿 뷰 완성.
