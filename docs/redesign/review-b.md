**조율안의 큰 방향에 동의한다.** B의 하단 탭바도 지도 공간을 확보하는 현재 결정으로 바꿀 수 있다. 우선 수정할 것은 시트 높이, 경로 출처 분류, 걷기길 표시 기준·수집 범위, 확대 조작이다. 브리프·세 제안·조율안·관련 코드·데이터·모바일 캡처를 대조했으며 파일은 변경하지 않았다.

**2. 사용자 요구에 영향이 큰 수정 5개**

1. **#5 시트 높이: 공간 절약을 작은 숫자로만 판단하면 조작이 깨진다.**  
   산 시트의 명시된 제목 48 + 메타 20 + 탭 44만으로 112px이다. 여기에 그래버·주의·첫 코스 행을 넣으면 160px을 넘는다. 목록 peek 88px의 도식에는 약속한 첫 행도 없다. **대안:** 목록 peek는 손잡이·결과 수, 산 peek는 이름·위치·경로 열기, 경로 peek는 이름·핵심 수치로 제한한다. 탭·코스 행·부가 동작은 half에 배치한다. 상단 바·안전영역·키보드를 실제 측정해 단계를 재계산한다. 화면 키보드가 레이아웃 뷰포트와 별개로 가시 영역을 줄일 수 있다는 설명을 확인했다. [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)

2. **#9 선 소스: 계산 GPX가 실측처럼 보일 수 있다.**  
   `src/routegpx.js`는 수록 코스 GPX를 “실측 GPS 기록이 아니라 … 계산한 경로”라고 명시한다. 따라서 ‘수록 GPX 우선·실선’은 출처 구분과 충돌한다. **대안:** 저장 형식과 별도로 `생성 방식·출처·확인일·대응 구간`을 보존한다. 계산 경로는 파일 위치와 무관하게 계산 라벨·점선을 적용한다. 공식 코스 설명 확인과 선형 검증도 분리한다. 실시간 계산 버튼은 설정 OFF에서 숨겨 토글 약속을 지킨다.

3. **#11 걷기길 표시: 같은 줌 숫자가 같은 지리적 범위를 뜻하지 않는다.**  
   Kakao는 작은 level일수록 확대되며 현재 코드의 Leaflet 줌 변환도 근사식이다. ‘줌 ≥10’을 그대로 적용하면 공급자별 발견성이 달라진다. [Kakao 공식 문서](https://apis.map.kakao.com/web/documentation/#Map_setMinLevel)  
   **대안:** 공통 m/px 또는 가시 범위 폭으로 표시 단계를 정한다. 전국에서는 길 이름·묶음과 확대 안내를 제공하고, 지역에서는 화면 안 선을 제한해 표시한다. 선택한 길은 제한과 관계없이 표시하되, 걷기길 모드의 “항상”도 과밀 제한을 따른다.

4. **#12 주변 범위: 산 주변 파일의 합집합은 전국 걷기길 목록이 아니다.**  
   조율안의 전국 `walks.json`을 산별 12km 파일만 합쳐 만들면, 모든 수록 산에서 먼 길은 누락된다. 정상과 가까워도 계곡·능선 때문에 접근하기 어려울 수도 있다. **대안:** 전국 relation 목록을 독립 수집하고 산별 파일은 연결 인덱스로 만든다. 주변 5/10km에는 **“정상에서 선까지 직선거리”**를 명시한다. 지리산·설악산처럼 넓은 산은 정상 밖 주요 접근 권역도 검토한다. 20km 선택 복원보다 수집 누락 방지가 우선이다.

5. **#14 확대 조작: 쉬운 조작을 설정 발견에 맡기지 않는다.**  
   터치 기기 사용자 모두가 핀치할 수 있는 것은 아니다. W3C는 지도 핀치의 단일 포인터 대안으로 확대·축소 버튼을 예시한다. [W3C Pointer Gestures](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)  
   **대안:** 지도 옆 기존 조작 묶음에 44px 이상의 `+ / −`를 기본 제공한다. 숨김은 사용자의 명시적 선택으로 하며, 숨긴 경우에도 지도 조작 메뉴에서 단일 탭으로 확대·축소할 수 있게 한다.

**3. 빠졌거나 깨지기 쉬운 것 — 최대 5개**

- **접근성·IME:** 검색 입력 중 결과 갱신마다 제목으로 포커스를 옮기면 조합이 끊긴다. 항목 선택 때만 이동한다. 모달에는 초점 제한·복귀·배경 비활성화를, 탭에는 키보드 전환을 명시한다.
- **딥링크·복귀:** `[×]`와 브라우저 뒤로를 무조건 같은 동작으로 만들면 기록·카탈로그에서 온 상세가 목록으로 돌아간다. 실제 진입 맥락을 복원하고 직접 진입만 상위로 보낸다. `t:<순번>`에는 안정 ID·이전 매핑이 필요하다.
- **공급자 차이:** 현재 Kakao `fitBounds`는 패딩 인자를 사용하지 않고 양 공급자 선은 점선 계약이 없다. full 상태의 가시 지도 면적은 사실상 0이므로 그때 경로 맞춤을 미루고 접힌 뒤 실행한다.
- **데이터 정직성:** 연결 277개·미연결 27개는 재확인했지만 연결이 구간 동일성을 증명하지 않는다. OSM 다중 선형의 순서·단절을 보존하고 GPX·고도에서 끊긴 구간을 연결하지 않는다. [OSM Route relation](https://wiki.openstreetmap.org/wiki/Relation:route#Order_matters)
- **성능·실패:** 전국 거친 선도 초기 일괄 수신을 피하고 지역별 지연 로드·캐시 제한을 둔다. 지도 실패 시 목록을 즉시 사용할 수 있게 한다. 지도 셸이 숨겨지면 추적·요청·이벤트를 중단하고 복귀 시 재배치한다.

**4. B에서 꼭 살릴 아이디어 — 최대 3개**

- **산에 연결되지 않은 걷기길도 전국 검색에서 찾기.** 데이터 범위를 넓히는 핵심이다.
- **조건 밖 검색 결과는 임시 선택으로 표시하기.** 기존 필터를 몰래 해제하지 않는다.
- **현위치 측정과 지속 추적 시작을 분리하기.** 같은 버튼의 두 번째 탭으로 추적을 켜기보다 명시적인 시작·종료를 제공한다.
